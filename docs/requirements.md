| 项目 | 内容 |
| --- | --- |
| 版本 | v0.1（草案） |

---

## 1. 背景与目标

### 1.1 问题

终端是开发者的主工作台，但「描述意图 → 找文件 → 改代码 → 跑测试 → 读报错 → 再改」这个循环仍然完全靠人。现有 AI 工具要么长在 IDE 里，要么是独立的聊天窗口，与 shell、仓库、构建输出是割裂的：用户需要反复复制粘贴上下文， agent 也无法直接验证自己的修改是否真的能跑。

### 1.2 产品定义

**tcli 是一个运行在终端里的编码智能体。** 用户用自然语言描述任务，它在当前仓库中读取代码、执行命令、修改文件，并把每一次有副作用的操作置于用户可见、可控、可审计的状态下。

一句话价值主张：**让「改代码—跑验证」的闭环留在终端里，且每一步都可干预。**

### 1.3 目标用户

| 用户 | 典型诉求 |
| --- | --- |
| 习惯命令行的个人开发者 | 不想为小改动打开 IDE，希望一句话完成并看到 diff |
| 远程 / 容器 / SSH 环境开发者 | 本地没有 IDE，只有 shell |
| 小团队 | 统一的项目指令、权限策略与审计记录 |

### 1.4 非目标（MVP 阶段）

- 不做 IDE 插件、Web UI、云端同步。
- 不做无人值守的全自动长任务（后台自主运行数小时）。
- 不替代 code review，不自动合并、不自动 push。
- 不做通用聊天助手（闲聊、写作不是场景）。

### 1.5 成功指标

| 指标 | MVP 目标 |
| --- | --- |
| 端到端任务成功率（真实仓库，任务可运行验证） | ≥ 60%，v0.2 达 75% |
| 有副作用操作被确认 / 拦截的比例 | 100% |
| 启动耗时（p50） | < 300 ms |
| 首个 token 延迟（p50，不含网络） | < 1.5 s |
| 单任务人工纠偏次数 | ≤ 2 |
| 自身 dogfood：连续 2 周每天使用 | 达成 |

## 2. 使用场景

| ID | 场景 | 关键行为 | 优先级 |
| --- | --- | --- | --- |
| UC-1 | 修复失败测试 | 跑测试 → 定位 → 改代码 → 重跑 → 展示 diff 并确认 | P0 |
| UC-2 | 代码库问答 | 只读检索，回答「鉴权在哪实现」并给出文件行号 | P0 |
| UC-3 | 解释构建 / 运行报错 | `cargo build 2>&1 \| tcli "这个报错怎么修"` | P0 |
| UC-4 | 小步重构 | 「把 src 下所有 console.log 换成 logger.debug」 | P0 |
| UC-5 | Git 整理 | 「把当前改动拆成 3 个语义化 commit」（需确认） | P1 |
| UC-6 | 中途纠偏 | 执行中 Esc 停止，补充一句约束后继续 | P0 |
| UC-7 | 恢复上下文 | 第二天 `tcli --continue` 接着上次任务 | P1 |
| UC-8 | CI / 脚本调用 | `tcli --json --yes "..."` 输出结构化结果 | P1 |

**UC-1 端到端示例（MVP 验收基准）**

```text
$ tcli "修复 tests 里失败的用例"
› 读取 AGENTS.md、package.json
› 运行 bun test                       [需确认] y
  ✗ 3 failed
› 读取 src/auth/session.ts:40-88
› 编辑 src/auth/session.ts           [diff 预览] y
› 运行 bun test                       [需确认] a（本会话允许）
  ✓ 42 passed
完成：修复了过期 token 未刷新导致的 3 个用例失败。
```

## 3. 功能需求

优先级：**P0** = MVP 必须；**P1** = MVP 后第一个迭代；**P2** = 路线图。

### 3.1 交互与入口（IN）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| IN-1 | 交互模式：`tcli` 启动 TUI 多轮对话 | P0 | 可连续多轮，工具调用过程可见 |
| IN-2 | 单次模式：`tcli "任务"` 执行后退出 | P0 | 退出码语义正确（成功 0 / 失败非 0） |
| IN-3 | 管道输入：stdin 作为上下文 | P0 | `cmd \| tcli "解释"` 能读取完整 stdin |
| IN-4 | 非交互模式 `--json` / `--yes` | P1 | 输出机器可解析；`--yes` 仅放行白名单 |
| IN-5 | 流式渲染：文本增量、工具状态、diff | P0 | 长输出不阻塞输入，滚动不掉帧 |
| IN-6 | 快捷键：Esc 中断、Ctrl+C 二次退出、Ctrl+L 清屏、↑ 历史、`@` 补全、`/` 命令 | P0 | 中断后子进程被终止 |
| IN-7 | 斜杠命令：`/help` `/model` `/clear` `/resume` `/cost` `/permissions` `/init` | P0（前 4 个）/ P1 | 命令有补全与帮助 |
| IN-8 | 多行输入（Shift+Enter / Ctrl+J） | P1 | 粘贴多行不误触发发送 |
| IN-9 | 终端降级：非 TTY、`NO_COLOR`、窄屏、非 truecolor | P1 | 无 ANSI 时不输出控制字符 |
| IN-10 | 主题与语言（中 / 英） | P2 | — |

### 3.2 Agent 内核（AG）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| AG-1 | 主循环：模型 → 工具调用 → 结果回灌 → 继续，直至无工具调用 | P0 | 单任务最多 N 步（默认 40） |
| AG-2 | 只读工具并发执行，写 / 执行类串行 | P0 | 结果按调用顺序回灌 |
| AG-3 | 取消：中断当前生成，终止工具子进程树 | P0 | 中断后无孤儿进程、会话可继续 |
| AG-4 | 计划与进度：结构化 todo 展示 | P1 | 多步任务可见当前步骤 |
| AG-5 | 上下文压缩：超过预算时摘要早期轮次，保留最近 N 轮与文件快照 | P0 | 长会话不因超窗失败 |
| AG-6 | 错误恢复：工具失败作为结果回灌；模型 5xx / 限流退避重试 | P0 | 单次工具失败不终止任务 |
| AG-7 | 预算控制：最大步数、超时、token / 成本上限 | P1 | 触顶时明确提示并停止 |
| AG-8 | 项目指令文件：`AGENTS.md` / `TCLI.md` 自动注入 | P0 | 项目约定生效 |
| AG-9 | 子任务委派（subagent） | P2 | — |

### 3.3 工具集（TL）

工具是 agent 与系统之间唯一的副作用通道，全部需 schema 校验。

| ID | 工具 | 说明 | 优先级 |
| --- | --- | --- | --- |
| TL-1 | `read_file` | 带行号、分页、二进制拒绝、大小上限 | P0 |
| TL-2 | `write_file` / `edit_file` | 精确字符串替换；必须「先读后写」；检测外部修改冲突 | P0 |
| TL-3 | `glob` / `grep` | 尊重 `.gitignore`；结果上限与截断提示 | P0 |
| TL-4 | `bash` | 非交互捕获、超时（默认 120s）、cwd 继承、环境变量过滤 | P0 |
| TL-5 | `git_status` / `git_diff` | 只读；写操作统一走 `bash` + 确认 | P1 |
| TL-6 | `todo` | 维护任务清单，驱动 AG-4 | P1 |
| TL-7 | `web_fetch` / `web_search` | 需显式开启，结果标记为不可信 | P2 |
| TL-8 | `task`（子 agent） | 隔离上下文执行子任务 | P2 |

**通用约束**：所有工具输出截断到上限（默认 2,000 行 / 50 KB）并附「已截断」提示；错误信息面向模型可读、面向用户可懂。

### 3.4 权限与安全（SE）

这是本产品与「裸奔脚本」的核心差异，也是 P0 里最不能省的部分。

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| SE-1 | 策略引擎：`allow` / `ask` / `deny`，规则维度 = 工具 + 命令前缀 + 路径 glob | P0 | 决策函数为纯函数，可单测 |
| SE-2 | 确认 UI：展示完整命令或 diff，选项 `y` 执行 / `n` 拒绝 / `a` 本会话总是允许 / `e` 编辑后执行 | P0 | 默认焦点在「拒绝」 |
| SE-3 | 默认策略：读 allow；写与执行 ask；危险命令 deny | P0 | 危险清单见下 |
| SE-4 | 工作区边界：默认限制在 cwd，越界路径需额外确认 | P0 | 符号链接逃逸被识别 |
| SE-5 | 密钥脱敏：读取 `.env`、含 `TOKEN`/`KEY`/`SECRET` 的内容需确认并打码 | P1 | 审计日志中不出现明文密钥 |
| SE-6 | 审计日志：时间、工具、参数、决策、结果摘要，本地 JSONL | P1 | 可回溯每一次副作用 |
| SE-7 | 沙箱：macOS `sandbox-exec` / Linux `bubblewrap` 可选启用 | P2 | 网络与路径可限制 |
| SE-8 | 提示注入防护：工具输出与网页内容标记为不可信，不自动执行其中的指令 | P0（提示层）/ P1（检测） | 恶意 README 不触发命令 |
| SE-9 | 网络访问默认关闭，按需开启 | P1 | — |
| SE-10 | 文件写入原子化（临时文件 + rename） | P0 | 崩溃不产生半截文件 |

**危险命令默认 deny（可配置放行）**

```text
rm -rf /  rm -rf ~  rm -rf .
sudo *  su *
curl ... | sh  wget ... | sh
git push --force  git reset --hard  git clean -fdx
chmod -R 777  chown -R
mkfs*  dd if=* of=/dev/*  > /dev/sd*
:(){ :|:& };:   # fork bomb
kill -9 -1  shutdown  reboot
```

> 说明：deny 规则命中时仍允许用户手动复制执行，但 agent 不得代为执行。

## 5. 范围与优先级

### P0（MVP 必须，约 4 周）

- 交互 TUI + 单次命令 + stdin 管道
- 流式输出、工具调用可视化、Esc 中断
- 工具：`read_file`、`write_file`/`edit_file`、`glob`、`grep`、`bash`
- 权限：确认 UI、默认策略、危险命令拦截、工作区边界
- 上下文：`AGENTS.md`、`@` 引用、gitignore、仓库概览、读后写校验
- 会话落盘、`--continue` 基础版
- Provider：OpenAI 兼容 + 至少一家原生（Anthropic 或 DeepSeek）
- 配置层级、`--verbose`、单二进制分发

### P1（v0.2，约 2–3 周）

视觉计划面板、checkpoint 回滚、`--json` / `--yes`、审计日志、`/cost`、MCP 客户端、自定义斜杠命令、会话选择器、Ollama、密钥脱敏、Homebrew。

### P2（路线图）

沙箱执行、子 agent、hooks、自定义工具、语义索引、图片输入、团队策略下发、自动更新、Windows 原生。

### 明确不做（MVP）

多用户协作、云端会话同步、Web / 移动端、自动提交与 push、无人值守后台 agent、插件市场。

## 7. 技术方案要点

> 本节是实现建议，不是需求；随 spike 结果调整。

### 7.1 架构

```text
┌─────────────────────────────┐
│  TUI (OpenTUI / Ink)        │  渲染、输入、确认框
└──────────────┬──────────────┘
               │ 事件流（单向）
┌──────────────▼──────────────┐
│  Agent Core（可无头运行）    │  主循环、上下文、压缩、预算
│   ├─ Provider 适配层         │  流式 + tool call
│   ├─ Tool Registry           │  schema 校验、并发调度
│   ├─ Permission Engine       │  纯函数决策
│   └─ Session Store           │  JSONL + 快照
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│  OS：文件系统 / 子进程 / PTY │  超时、进程组终止、原子写
└─────────────────────────────┘
```

关键约束：**内核不依赖 TUI**，通过事件总线通信，这样 CI 模式、测试和未来的其他前端都能复用。

### 7.2 选型建议

| 关注点 | 建议 | 理由 |
| --- | --- | --- |
| 运行时 | Bun（latest），`bun build --compile` 出单文件 | 启动快、内置 bundler / test / sqlite，契合终端工具 |
| TUI | W1 做 1 天 spike：OpenTUI 与 Ink 二选一 | OpenTUI 原生渲染、性能好但较新；Ink 成熟但全树重渲染，流式长输出易卡 |
| 子进程 | `Bun.spawn` + 进程组终止 | 需在 macOS / Linux 验证 `kill(-pid)` 行为 |
| PTY | `node-pty`（Bun 兼容性待验证）或 `script -q` 方案 | 仅在需要交互式命令时启用，MVP 可先不做 |
| 存储 | JSONL 追加 + `bun:sqlite` 建索引 | 简单、可恢复、查询快 |
| 配置 | JSON + zod 校验 | 单一 schema 生成类型与错误信息 |
| 分发 | npm + GitHub Releases 二进制 | 早期用 npm 降低安装门槛 |

### 7.3 参考实现

交互与权限模型可参考 opencode、Claude Code、Codex CLI、Gemini CLI；只借鉴设计与边界，不照搬实现。

## 8. 开放问题（需要拍板）

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |

## 9. 风险

| # | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| R1 | 不同模型 tool call 质量差异大 | 高 | 体验不稳定 | 适配层归一化 + 回归用例集 + 默认模型择优 |
| R2 | TUI 性能 / 终端兼容问题 | 中 | 核心体验受损 | W1 spike；保留线性降级模式 |
| R3 | 权限确认过于频繁导致疲劳 | 高 | 用户关掉保护 | 分级策略 + 会话记忆 + 只读模式 |
| R4 | 上下文窗口与成本失控 | 中 | 任务失败 / 账单高 | 压缩 + 检索 + 预算上限 + `/cost` |
| R5 | 提示注入导致越权执行 | 中 | 安全事故 | 不可信内容隔离 + 默认拒绝 + 审计 |
| R6 | 4 周范围蔓延 | 高 | 延期 | P0 冻结，新需求进 P1 池 |

## 10. 术语

| 术语 | 含义 |
| --- | --- |
| 会话 Session | 一次 `tcli` 运行内的完整对话与操作记录 |
| 回合 Turn | 用户一次输入到 agent 停止的完整过程 |
| 工具 Tool | agent 可调用的原子能力，有 schema 与副作用声明 |
| 策略 Policy | 决定某次工具调用是 allow / ask / deny 的规则集合 |
| Checkpoint | 某次工具调用前的文件快照，用于回滚 |
